# LCP Optimization Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce LCP from 8+ seconds to <2.5s on mobile for homepage, blog listing, and quote page.

**Architecture:** Three root causes: (1) hero images have no `<link rel="preload">` so the browser discovers them late; (2) `cmsImage()` sets `src` to the largest width (1920px), punishing mobile; (3) `decoding="async"` and universal `loading="lazy"` on above-fold images delay paint. Fix by adding preload hints in server-rendered page JSX, making `cmsImage()` mobile-first, removing paint-blocking attributes from LCP images, and eagerly loading first blog cards.

**Tech Stack:** Next.js App Router, `cmsImage()` helper, Directus asset transforms (already handles WebP/resize)

### Task 2: Fix Hero.tsx — remove `decoding="async"`, add preload support

**Files:**
- Modify: `src/components/Hero.tsx:34-41`

The homepage hero image is the LCP element. `decoding="async"` tells the browser it's OK to defer decoding, which delays paint for the very element we need painted fastest. Also, the `sizes` attribute generated by `cmsImage()` is suboptimal — on mobile (<640px) it still requests 640px. Use an explicit sizes string.

- [ ] **Step 1: Fix hero image attributes**

In `src/components/Hero.tsx`, replace the `<img>` element (lines 34-42):

```tsx
<img
  src={optimised.src}
  srcSet={optimised.srcSet}
  sizes="(max-width: 640px) 640px, (max-width: 1024px) 1024px, 1920px"
  alt=""
  fetchPriority="high"
  className="w-full h-full object-cover object-center"
/>
```

Changes: removed `decoding="async"`, improved `sizes` with explicit mobile breakpoint.

- [ ] **Step 2: Add `preloadSrc` prop to Hero for preload hints**

Add an optional `preloadImage` prop to `HeroProps`:

```ts
interface HeroProps {
  // ... existing props
  preloadImage?: { srcSet: string; sizes: string };
}
```

When provided, render a `<link rel="preload">` that gets hoisted to `<head>` by Next.js:

```tsx
{preloadImage && (
  <link
    rel="preload"
    as="image"
    imageSrcSet={preloadImage.srcSet}
    imageSizes={preloadImage.sizes}
  />
)}
```

Place this at the top of the returned JSX (before the `<section>`). Next.js App Router automatically hoists `<link>` tags to `<head>`.

Expected: no errors
